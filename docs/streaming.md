# Лайвстриминг

Два независимых вопроса: **чем рисовать аватара** и **куда отдавать картинку**.
Их можно комбинировать как угодно — локальный риг можно стримить, провайдерского
аватара можно просто смотреть в превью.

## Выбор провайдера

Сначала развилка, которая важнее любого рейтинга.

| | Локальный риг (в этом репозитории) | Провайдер |
|---|---|---|
| Чем ведётся | **вашим лицом** с камеры | **звуком**: моделью по речи |
| Ваши повороты головы и мимика | переносятся | **не переносятся**, генерируются заново |
| Реализм | плоская 2D-кукла | фотореализм |
| Цена кадра | 0 | поминутная |
| Задержка | нет | 150–500 мс |

То есть провайдер — это не «улучшенная версия» фильтра, это другой продукт.
Вы получаете фотореалистичного ведущего, который говорит вашим голосом, но
жестикулирует и двигает головой по-своему.

### Рекомендация: LiveAvatar (HeyGen), режим LITE

Взят как **самый качественный по картинке**. По сравнениям 2026 года HeyGen
лидирует по реализму аватаров и размеру библиотеки, включая 1080p, а LiveAvatar
работает в продакшене у Coursera, HP и Bosch. Компания дольше всех в этой нише.

Режим **LITE** («Avatar Only») подходит нам точно: провайдер занимается только
рендером видео по нашему звуку, никакого своего LLM и TTS. Это и дешевле
(1 кредит в минуту против 2 у FULL), и оставляет ваш голос вашим.

Качество выставлено на максимум — `video_settings.quality: "very_high"`
(шкала `very_high | high | medium | low`), кодек H264.

### Альтернативы, если LiveAvatar не подойдёт

- **Anam** — модель CARA-3 заявляет первое место в Avatar Benchmark 2025 и самую
  низкую задержку (~150–180 мс на генерацию, медиана диалога меньше секунды).
  Берите, если задержка важнее картинки.
- **Tavus** — сильнее всех, когда нужна **копия конкретного человека**, а не
  аватар из каталога; отдельная модель восприятия (Raven) умеет читать эмоции.
- **Simli** — самый простой API для «аватар говорит моим голосом»: метод
  `listenToMediastreamTrack(track)` принимает дорожку микрофона напрямую.
  Качество ниже, зато интеграция в несколько строк.

Все четверо доступны и как плагины LiveKit Agents, если вы строите голосового
агента, а не стрим.

## Два голосовых режима

Сессия у провайдера одна и та же, меняется только источник звука.

| | Мой голос | Синтез голоса |
|---|---|---|
| Что подаётся | микрофон, как есть | текст, который озвучивает TTS |
| Голос в эфире | ваш | выбранный голос ElevenLabs |
| Задержка | поток идёт чанками по секунде | пауза на синтез фразы |
| Нужен ключ | только провайдера | ещё и ElevenLabs |
| Когда полезно | вы ведёте эфир сами | заготовленные реплики, чужой язык, работа без микрофона |

**Мой голос** — микрофон захватывается через AudioWorklet, контекст создаётся
сразу на 24 кГц (браузер передискретизирует сам), куски по секунде уходят в
PCM16 и дальше провайдеру.

**Синтез голоса** — текст уходит на сервер, тот зовёт ElevenLabs с
`output_format=pcm_24000`. Это ровно тот формат, который ждёт аватар, поэтому
перекодирования нет вообще: ответ режется на секундные чанки и отправляется как
есть. Новая фраза сначала перебивает предыдущую, иначе они склеятся в одну.

Модель по умолчанию — `eleven_multilingual_v2`, она нормально говорит
по-русски. Меняется переменной `ELEVENLABS_MODEL`.

Переключаются они в окне «Эфир», разделом «Чем говорит», прямо на живой
сессии: микрофон поднимается и глушится на лету, пересоздавать сессию не нужно.

## Как это включить

Провайдеру нужен сервер: ключ API не должен попадать в браузер. Сервер в
репозитории не тянет зависимостей — Node 22 умеет `fetch` и `WebSocket` сам.

PowerShell:

```powershell
$env:LIVEAVATAR_API_KEY = 'ключ-провайдера'
$env:ELEVENLABS_API_KEY = 'ключ-синтеза'
$env:ELEVENLABS_VOICE_ID = 'id-голоса-по-умолчанию'
node server/live-server.mjs
```

cmd.exe — `set LIVEAVATAR_API_KEY=...`, bash — `export LIVEAVATAR_API_KEY=...`.
Переменные живут только в текущем окне; чтобы не вводить их каждый раз,
пропишите их в системные переменные среды.

Ключи независимы: без `ELEVENLABS_API_KEY` работает режим «Мой голос», без
`LIVEAVATAR_API_KEY` — всё, кроме провайдерского аватара.

Он же раздаёт статику, так что `npx serve` больше не нужен — открывайте
`http://localhost:5173`. Без ключа всё остальное работает, а провайдерский
аватар честно сообщает, что каталог недоступен.

Дальше в окне «Эфир»: галочка «Фотореалистичный аватар провайдера» → выбрать
аватара из каталога. Кадр от провайдера приходит со своим фоном, поэтому он режется той
же сегментацией, что и человек в режиме «Я на фоне», и ставится на сцену из
Higgsfield.

Что происходит под капотом:

```
микрофон → PCM16 24 кГц, чанки по секунде → наш сервер → WebSocket агента
                                                              ↓
                                            LiveAvatar рендерит видео
                                                              ↓
                                        комната LiveKit → браузер
                                                              ↓
                               сегментация → композит с фоном → канвас
```

## Куда отдавать картинку

### OBS — самый надёжный путь

Browser Source на `http://localhost:5173`, размер 1280×720. Дальше OBS сам
раздаёт на Twitch, YouTube, VK Video — куда угодно по RTMP. Ничего настраивать
в проекте не нужно, и это единственный способ попасть на площадки, которые
принимают только RTMP: браузер RTMP не умеет в принципе.

### WHIP — прямо из браузера

Поле «WHIP URL» в окне «Эфир», раздел «Куда отдавать». Работает с Cloudflare Stream, Livepeer, Dolby,
MediaMTX, OvenMediaEngine, Janus — со всем, что принимает WebRTC-HTTP Ingestion
(RFC 9725). Битрейт выставлен 4 Мбит/с при 30 кадрах.

Звук в эфир берётся автоматически: голос аватара, если работает провайдер, иначе
обычный микрофон.

Самая частая причина, по которой не подключается, — **CORS**: эндпоинт должен
разрешать запрос из браузера. Если провайдер этого не умеет, остаётся OBS.

## Что проверено, а что нет

Проверено вживую: сервер поднимается, отдаёт статику, блокирует выход за корень
проекта и без ключа возвращает внятную ошибку. WHIP-издатель действительно
собирает SDP, применяет настройки битрейта, ждёт ICE и корректно разбирает
ответ — ошибки на нерабочем эндпоинте отрабатывают без падений.

**Не проверено**, потому что нужен платный аккаунт: весь путь с реальным ключом
LiveAvatar. Код написан строго по официальной документации, но три места стоит
проверить первыми:

1. **Авторизация WebSocket агента.** Мы открываем `ws_url` как есть, без
   дополнительных заголовков. Если провайдер потребует Bearer на этом сокете,
   нативный `WebSocket` в Node заголовки не умеет — понадобится пакет `ws`.
2. **Форма каталога аватаров.** Код принимает и массив, и `{items: [...]}`,
   и поля `id` / `avatar_id` — но если структура окажется иной, список будет пуст.
3. **Синтез.** Запрос к ElevenLabs и нарезка на чанки написаны по документации,
   но вживую без ключа не прогонялись. Проверено только то, что без ключа
   список голосов пуст, а «Сказать» без сессии даёт внятную ошибку.
