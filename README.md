# ai-avatar-proto

Записываете видео — получаете то же видео, где вместо вас ИИ-аватар, а вместо
комнаты сцена из Higgsfield. Голос и мимика остаются вашими: аватар повторяет
движения головы, взгляд, моргание и артикуляцию из исходной записи, а звуковая
дорожка переносится без изменений.

Есть и живой режим: то же самое в реальном времени как фильтр на камеру, с
выходом в эфир через WHIP или OBS — и с возможностью подменить плоского
персонажа фотореалистичным аватаром провайдера.

Ноль зависимостей, ноль оплаты за кадр: трекинг лица и сегментация считаются
локально через [MediaPipe Tasks Vision](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker)
(WASM + GPU), видео с камеры никуда не отправляется. Сервер в комплекте нужен
только чтобы раздать статику и спрятать ключи провайдера — вся обработка
остаётся в браузере.

## Запуск

Нужен **Node 22 или новее** — сервер использует встроенные `fetch`, `WebSocket`
и чтение `.env`, зависимостей у проекта нет вообще.

**Windows:** двойной клик по [run.cmd](run.cmd). Он сам находит Node, даже если
его нет в PATH, подхватывает ключи из `.env` и поднимает сервер.

**Любая система:**

```bash
node --env-file-if-exists=.env server/live-server.mjs
```

Дальше откройте `http://localhost:5173` и нажмите «Включить камеру» — либо
«Работать с файлом без камеры», если хотите только обработать готовое видео.
Первый запуск скачивает модели MediaPipe с CDN (~5 МБ), дальше они кешируются.

Ключи не нужны: без них работают и живой режим, и обработка видео. Они
понадобятся только для фотореалистичного аватара и синтеза голоса — скопируйте
[.env.example](.env.example) в `.env` и заполните нужные строки.

Открыть страницу просто файлом не получится: с `file://` браузер не даёт доступ
к камере. Если лайв-режим не нужен, подойдёт любой статический сервер,
например `npx --yes serve -l 5173 .`

> В Windows PowerShell 5.1 нет оператора `&&` — команды разделяйте `;`.
> Переменные окружения там задаются как `$env:ИМЯ = 'значение'`, а не `set ИМЯ=...`.

## Интерфейс

Всё, что нужно постоянно, вынесено в нижний тулбар: источник кадра
(«Аватар» / «Я на фоне»), выбор сцены, запись и снимок. Остальное живёт в
отдельных окнах, чтобы не превращать экран в стену тумблеров:

| Окно | Что внутри |
|---|---|
| **Видео → видео** | исходник (запись с камеры или файл) и его обработка |
| **Эфир** | кто в кадре, чем говорит, куда отдавать поток |
| **Настройки** | калибровка позы, параллакс, маска сегментации, слои аватара, отладка |

Короткие сообщения — что модель загрузилась, что файл сохранён — показываются
строкой поверх кадра и сами исчезают.

## Основной сценарий: видео → видео

1. **Записать исходник** прямо во вкладке (камера + микрофон) или **Открыть файл**
   с готовой записью — камера для этого не нужна.
2. Выбрать режим и сцену.
3. **Обработать в аватара** — готовый `.webm` сам упадёт в загрузки.

Обработка идёт в реальном времени: минута ролика — минута работы. Исходник
проигрывается, каждый кадр проходит трекинг и отрисовку, а результат пишется с
канваса вместе с оригинальным звуком. Если во время обработки уйти на другую
вкладку, конвейер замирает целиком (и видео, и запись) и продолжает с того же
места — иначе звук уехал бы относительно картинки.

Нейтральная поза для файла берётся автоматически по первым ~1.2 секундам записи:
медиана позы головы становится нулём. Для живого режима есть кнопка «Калибровать».

## Лайв и эфир

Локальный риг ведётся вашим лицом, провайдерский аватар — звуком: он даёт
фотореализм, но ваши повороты головы и мимика в кадр не переносятся, модель
генерирует их заново. Это разные продукты, а не разные уровни качества.

В качестве провайдера выбран **LiveAvatar (HeyGen) в режиме LITE** — по
сравнениям 2026 года он лидирует по реализму картинки, а LITE отдаёт нам рендер
видео по нашему же звуку, без чужого LLM и TTS. Качество выставлено на максимум
(`very_high`). Альтернативы и обоснование — в [docs/streaming.md](docs/streaming.md).

Картинку можно отдать в эфир двумя путями: **WHIP** прямо из браузера
(Cloudflare Stream, Livepeer, MediaMTX и прочие) или **OBS** через Browser
Source — единственный вариант для площадок с RTMP, который браузер не умеет.

Голос у провайдерского аватара бывает двух видов: **мой голос** (микрофон идёт
провайдеру как есть) и **синтез голоса** (текст озвучивается через ElevenLabs
в `pcm_24000` — ровно тот формат, который ждёт аватар, так что перекодирования
нет). Режимы переключаются на живой сессии.

Провайдеру нужен ключ, а ключ нельзя показывать браузеру, поэтому для этого
режима и существует `server/live-server.mjs`. Ключи независимы: без ключа
синтеза остаётся «мой голос», без ключа провайдера работает всё остальное.

## Два режима

| Режим | Что происходит | Higgsfield даёт |
|---|---|---|
| **Аватар** | нарисованный персонаж повторяет мимику, поворот головы, взгляд, моргание и артикуляцию; человека в кадре нет | слои персонажа + фон |
| **Я на фоне** | сегментация вырезает человека из кадра и ставит на сгенерированный фон | фон |

Без единого ассета прототип работает на процедурной заглушке — персонаж и фоны
рисуются кодом. Ассеты подставляются по одному, без правок кода.

## Как это устроено

```
камера или файл ──> FaceLandmarker ──> 478 точек + 52 блендшейпа + поза
                                      │
                                 signals.js   сглаживание, калибровка, выбор виземы
                                      │
                    ┌─────────────────┴─────────────────┐
                    │                                   │
                 rig.js                            cutout.js
        слои 1024×1024 + правила              ImageSegmenter вырезает вас
                    └─────────────────┬─────────────────┘
                                      │
                                  scene.js      фон + параллакс по голове
                                      │
                                   канвас ──> превью / WebM со звуком исходника
```

| Файл | Ответственность |
|---|---|
| [js/tracker.js](js/tracker.js) | загрузка моделей MediaPipe, камера, фолбэк GPU→CPU |
| [js/signals.js](js/signals.js) | точки и блендшейпы → компактный набор сигналов |
| [js/rig.js](js/rig.js) | слои и правила анимации (`bind`) |
| [js/placeholder.js](js/placeholder.js) | процедурный персонаж и фоны, когда ассетов нет |
| [js/scene.js](js/scene.js) | фон: картинка, видео-луп или градиент, параллакс |
| [js/cutout.js](js/cutout.js) | сегментация и композитинг режима «Я на фоне» |
| [js/recorder.js](js/recorder.js) | запись живого канваса с микрофоном, снимки |
| [js/pipeline.js](js/pipeline.js) | запись исходника и прогон файла через конвейер |
| [js/live.js](js/live.js) | публикация кадра в эфир по WHIP |
| [js/provider.js](js/provider.js) | фотореалистичный аватар провайдера, микрофон → PCM16 |
| [server/live-server.mjs](server/live-server.mjs) | статика и сессии провайдера; ключ живёт только здесь |

### Сигналы, которыми управляется аватар

Вся математика — в зеркальном пространстве (`x' = 1 - x`), чтобы правая сторона
пользователя совпадала с правой стороной экрана.

- **поза головы** считается по точкам (наклон линии глаз, смещение носа), а не по
  матрице трансформации — так предсказуемее знаки и проще калибровка;
- **зеркало отключается**: живое превью зеркалим, потому что так привычно, а файл
  обрабатываем как есть, иначе результат окажется отражением исходника. При
  выключенном зеркале стороны блендшейпов меняются местами — это учтено;
- **кнопка «Калибровать»** делает текущую позу нейтральной, это снимает почти всю
  возню с подгонкой констант под конкретную камеру и посадку;
- **сглаживание** кадронезависимое (экспоненциальное по `dt`), у моргания постоянная
  времени втрое меньше, иначе блинк выглядит вялым.

### Контракт слоёв

Слой — PNG 1024×1024 с прозрачностью, персонаж на всех слоях в одних координатах
(как экспорт слоёв из PSD). Что делает слой, описывает `bind` в
[assets/avatar.json](assets/avatar.json):

| `bind` | Поведение |
|---|---|
| — | едет вместе с группой (`head` или `body`) |
| `iris` | смещается по взгляду и повороту головы |
| `eyelid` | сжимается по вертикали от `pivot` пропорционально морганию |
| `brow` | поднимается и опускается |
| `mouth` | показывается, когда текущая визема равна `viseme`, и тянется по раскрытию |

Пока слоёв нет, в манифесте стоит `"assets": false` — код сразу берёт заглушки и не
дёргает несуществующие файлы. Положили PNG в `assets/layers/` — поменяйте на `true`
(у сцен то же самое, поле `ready` у каждой записи в `assets/scenes.json`).

Как сгенерировать слои и фоны в Higgsfield — в
[prompts/higgsfield-assets.md](prompts/higgsfield-assets.md), там же промпты и таблица файлов.

## Что это не умеет

- **Не разговаривает сам.** Аватар повторяет вас, а не отвечает за вас.
  Чтобы он вёл диалог, нужен голосовой агент (STT+LLM+TTS) — провайдер из
  лайв-режима уже умеет принимать чужой звук, так что достаточно подать ему
  не микрофон, а синтезированную речь.
- **Сцена не живая.** Обстановка — заранее отрендеренный слой; реагировать она может
  только параллаксом и переключением, но не генерироваться на лету.
- **Плоский риг.** Сильный поворот головы выглядит как поворот бумажной куклы;
  для настоящего объёма нужен 3D (Three.js + VRM).

## Ограничения обработки

- Скорость — 1:1 к длительности. Пережать быстрее можно только через WebCodecs
  (`VideoDecoder`/`VideoEncoder`), это заметно больше кода.
- Выход — WebM (VP9/VP8 + Opus). Для MP4 нужен отдельный перегон, например ffmpeg.
- Если трекинг не успевает за 30 fps, часть кадров повторится; звук при этом
  не разъезжается, потому что пишется одной дорожкой параллельно.

## Требования

Chrome/Edge/Firefox с поддержкой WebGL2 и `getUserMedia`. Только `https://` или
`localhost` — в незащищённом контексте браузер не отдаст камеру.
